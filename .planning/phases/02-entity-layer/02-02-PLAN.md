  <action>
1. Create `src/lib/validations/campaign.ts`:
   - `createCampaignSchema`: name (string, min 1 "Name ist erforderlich", max 50), color (string, regex /^#[0-9A-Fa-f]{6}$/), start_date (string nullable optional), end_date (string nullable optional), description (string nullable optional, max 500)
   - `updateCampaignSchema`: same fields but all optional

2. Create `src/lib/validations/hashtag-set.ts`:
   - `createHashtagSetSchema`: name (string, min 1, max 50), hashtags (array of strings, min 1 "Mindestens ein Hashtag erforderlich"), category (z.enum(["brand", "produkt", "kampagne"]).nullable().optional())
   - `updateHashtagSetSchema`: same fields but all optional

3. Create `GET /api/campaigns` -- query campaigns where is_active=true, order by created_at desc. For each campaign, also fetch post count via a subquery or separate count query on posts table where campaign_id matches. Return { data: campaigns[] } where each campaign includes `post_count: number`.

4. Create `POST /api/campaigns` -- validate body with createCampaignSchema. Get user via getUser(). Generate slug from name (lowercase, replace spaces with hyphens, remove non-alphanumeric). Insert with created_by = user.id. Return { data: campaign } with status 201.

5. Create `PATCH /api/campaigns/[id]` -- validate body with updateCampaignSchema. If name changed, regenerate slug. Update and return { data: campaign }.

6. Create `DELETE /api/campaigns/[id]` -- soft delete: set is_active=false. Return { data: { id } }.

7. Create `GET /api/hashtag-sets` -- query all hashtag_sets ordered by category, then name. Return { data: hashtagSets[] }.

8. Create `POST /api/hashtag-sets` -- validate with createHashtagSetSchema. Ensure each hashtag in array starts with "#" (prepend if missing). Get user, insert with created_by. Return { data } with 201.

9. Create `PATCH /api/hashtag-sets/[id]` -- validate with updateHashtagSetSchema. Same hashtag normalization. Update and return { data }.

10. Create `DELETE /api/hashtag-sets/[id]` -- hard delete (hashtag sets have no foreign key references from posts). Return { data: { id } }.

All routes: authenticate via supabase.auth.getUser(), mutation routes check for editor or admin role. Use .throwOnError() pattern from research to ensure errors propagate. Return consistent { data } / { error } envelope.
  </action>
