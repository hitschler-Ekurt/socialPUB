<decisions>
## Implementation Decisions

### Channel connection flow
- "+" Kanal verbinden" button opens a modal wizard: pick platform (Instagram/TikTok) > OAuth redirect to Late.dev > return to modal showing success/error
- Channel list displayed as a card grid (2-5 channels expected): platform icon, account name, avatar, status badge, last synced date
- Token health shown as colored status badge on each card: green "Verbunden", yellow "Laeuft bald ab" (<7 days), red "Getrennt"
- Card actions via dropdown menu: "Neu verbinden" (re-OAuth) and "Trennen" (soft-disconnect with confirmation) — admin-only

### Campaign management
- Color-coded cards with campaign color as left border/accent, showing name, date range, post count
- Creation via inline modal dialog: name, color picker (preset palette of 8-10 brand-friendly colors), start date, end date, optional description
- Campaigns and Hashtag-Sets live on a combined page ("Kampagnen") with two tabs — reuses tab pattern from Phase 1 Settings page

### Hashtag set management
- Categorized list grouped by category (Brand, Produkt, Kampagne) per HASH-03 requirement
- Each set shows: name, category badge, hashtag count, preview of first few tags
- Click to expand/edit inline

### Media library
- Thumbnail grid layout (Pinterest/Google Photos style) with filter bar at top: type (Image/Video/All), tags, campaign
- Hover on thumbnail shows filename + dimensions, click opens detail panel
- Upload via full-width drag-drop zone at top of page (dashed border, hitschies accent) + "Hochladen" button for file picker, multi-file support, inline upload progress with thumbnails appearing as they complete
- Tagging happens after upload in the detail view — no friction during upload, tag when organizing
- Bulk operations: checkbox on hover per thumbnail, toolbar appears when selected ("Tags hinzufuegen", "Loeschen", "X ausgewaehlt")
- Video thumbnails auto-generated by system (MEDIA-05)

### Shared layout pattern
- All entity pages share a consistent shell: page title + description, action button top-right ("+ Neu"), filter bar below header
- Content area varies by domain: cards for channels/campaigns, categorized list for hashtags, thumbnail grid for media
- Empty states: branded with hitschies-themed icon, friendly German message (e.g., "Noch keine Kanaele verbunden"), primary CTA button ("Ersten Kanal verbinden") — actionable evolution of Phase 1 coming-soon pages
- All CRUD operations use Dialog modals (create/edit) and confirmation dialogs (delete) — stays in context, consistent with channel connection wizard
- Role-based: Viewers see all data but action buttons ("+ Neu", edit, delete) are hidden — consistent with Phase 1 "see everything, actions hidden" decision, RLS enforces server-side

### Claude's Discretion
- Exact color palette choices for campaign color picker
- Media detail panel layout (side panel vs full modal)
- Filter component design and interaction patterns
- Loading states and skeleton patterns for grids/lists
- Exact empty state illustration/icon choices
- Pagination vs infinite scroll for media grid (likely pagination given Supabase)

</decisions>

<specifics>
## Specific Ideas

- Design consistent with "Playful Professional" — 80% clean & functional, 20% hitschies personality (carried from Phase 1)
- Design references: Notion clarity + Linear aesthetics + hitschies colors
- Campaigns are seasonal (Karneval, Halloween, Weihnachten, Sommer) — preset color palette should include hitschies brand colors
- Hashtag sets serve one-click insertion in composer (Phase 3) — the list view should make sets easy to browse and understand at a glance
