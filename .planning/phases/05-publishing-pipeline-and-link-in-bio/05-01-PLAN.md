   - `ACTION_ROLES` map: submit_review->["admin","editor"], approve->["admin"], reject->["admin"], schedule->["admin","editor"], retry->["admin","editor"]
   - `ACTION_TO_STATUS` map: submit_review->"review", approve->"approved", reject->"draft", schedule->"scheduled", retry->"scheduled"
   - `validateTransition(currentStatus, action, userRole)` function that returns `{ valid: boolean, targetStatus?: string, error?: string }`

1. **Create src/app/api/posts/[id]/workflow/route.ts** -- POST handler:
   - Auth check via getUser() + profile role lookup (same pattern as posts/[id]/route.ts)
   - Parse body with workflowActionSchema
   - Fetch current post status from DB
   - Call validateTransition(currentStatus, action, userRole)
   - If invalid: return 400 with error message
   - If valid: update post status to targetStatus
   - For "reject" action: also set review_comment on the post (add to update object). Note: posts table does not have review_comment column -- store in publish_errors JSONB as { review_comment, reviewed_by, reviewed_at } for simplicity without schema migration
   - For "schedule" action: also set scheduled_at from request body (required)
   - For "retry" action: clear publish_errors, set scheduled_at to original scheduled_at value
   - Insert row into approval_logs table with action, comment, performed_by
   - Return updated post with 200

2. **Create src/hooks/use-workflow.ts** -- TanStack Query mutation:
   - `useWorkflowAction()`: mutationFn calls POST /api/posts/{id}/workflow with { action, comment?, scheduledAt? }
   - Invalidates queryKey ["posts"] and ["calendar-posts"] on success
   - Returns the mutation object

3. **Create bio API routes** following existing CRUD patterns (see posts/route.ts, campaigns route):
   - `src/app/api/bio/route.ts`: GET (list pages for current user), POST (create page with slug uniqueness check)
   - `src/app/api/bio/[pageId]/route.ts`: GET (single page with items), PATCH (update page), DELETE (delete page)
   - `src/app/api/bio/[pageId]/items/route.ts`: GET (items with link data), POST (add item), PATCH (reorder items -- accepts array of {id, position}), DELETE (remove item by id in query param)
   - All bio routes require editor/admin role (same auth pattern)
   - Add a public bio data route at `src/app/api/bio/public/[slug]/route.ts`: GET without auth, fetches page by slug with active non-expired items, for the public bio page to consume

4. **Create src/hooks/use-bio-pages.ts** -- TanStack Query hooks:

   - `useCreateBioPage()`: POST /api/bio, invalidates ["bio-pages"]
   - `useUpdateBioPage()`: PATCH /api/bio/{pageId}, invalidates ["bio-pages"]
   - `useDeleteBioPage()`: DELETE /api/bio/{pageId}, invalidates ["bio-pages"]

   - `useRemoveBioItem()`: DELETE /api/bio/{pageId}/items?itemId=X, invalidates ["bio-items"]
